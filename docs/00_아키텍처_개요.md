## 1. 개관 — 논리 3계층 → 물리 컴포넌트
기획서의 논리 3계층(센싱 → 판단 → 관계)을 물리 컴포넌트로 매핑한다. **핵심: 거의 모든 처리가 자녀 폰 안에서 끝나고, 네트워크를 넘는 것은 다이제스트뿐이다.**

```
┌──────────────────────────── 자녀 폰 (on-device) ────────────────────────────┐
│                                                                              │
│  [센싱]  AccessibilityService ──┐                                            │
│          UsageStatsManager  ────┼──▶ EphemeralSignal (메모리 전용, 미저장)    │
│          시스템 시계        ────┘            │                                │
│                                              ▼                                │
│  [판단]  A축 분류기(ONNX) ── 연령가 매핑 ──┐                                  │
│          B축 신호 규칙 엔진  ──────────────┼──▶ 개입 판단 / 일일 패턴 집계     │
│                                            ▼                                  │
│  [관계]  라우터(intent 분류) ──▶ 응답 뱅크 선택 ──▶ 오디오 재생 + 요정 UI    │
│                                            │                                  │
│          로컬 상태(요정 관계·기억·집계 패턴) ── 암호화 저장                   │
│                                            │                                  │
│                          ┌─────────────────┘                                 │
│                          ▼                                                    │
│            DigestBuilder ── 가명·집계 ── DigestPayload (유일한 송신 게이트)   │
└──────────────────────────────────┬───────────────────────────────────────────┘
                                    │ (다이제스트만)
                                    ▼
                       ┌──────── 백엔드 (FastAPI) ────────┐
                       │  계정·페어링·동의확인·결제        │
                       │  다이제스트 중계 (저장 최소화)     │
                       │  응답뱅크/모델 OTA 배포           │
                       └──────────────┬───────────────────┘
                                      ▼
                            ┌──── 부모 폰 ────┐
                            │ 맥락 카드 표시   │
                            │ 페어링·동의      │
                            └─────────────────┘
```

## 2. 데이터 플로우 (정상 경로)
1. **센싱**: AccessibilityService가 포그라운드 앱·node-tree 텍스트·전환 이벤트를, UsageStats가 세션 통계를 수집 → 모두 `EphemeralSignal`(메모리 전용).
2. **A축 판단**: 현재 콘텐츠의 연령가 결정. 등급 있으면 공식 등급, 없으면 ONNX 분류기로 등가 연령가 추정 → **임계 비교 후 라벨 폐기.**
3. **B축 판단**: 사용패턴 신호를 규칙 엔진에 통과 → 강박/중독 점수, 개입 트리거 여부.
4. **관계(개입/대화)**: 판단 결과 + 상황 → 라우터가 intent 선택 → 응답 뱅크에서 대사·오디오 선택 → 요정이 재생. 결과(수락/거절 등)는 로컬 관계 상태에 반영.
5. **집계**: 하루 동안 *원시가 아닌 집계 지표*(개입 횟수·수락률·관심 콘텐츠의 '결' 등)만 로컬에 누적.
6. **다이제스트**: 주기적으로 `DigestBuilder`가 집계를 가명·추상화해 `DigestPayload` 생성 → 백엔드 경유 → 부모 폰.

> **신뢰 경계**: 점선(네트워크)을 넘는 데이터는 `DigestPayload` 한 종류뿐. 코드상 다른 어떤 모듈도 직접 네트워크 송신을 하지 않는다(CLAUDE.md §6).

## 5. 백엔드 서비스 맵 (FastAPI · 구현 후순위, 현재 API 명세만 → `docs/40`)
| 서비스 | 책임 | 데이터 보존 |
|---|---|---|
| `auth` | 부모 계정·세션 | 표준 |
| `consent` | 동의 확인 기록(§17조의2 충족 증빙) | 동의 메타만 |
| `pairing` | 자녀-부모 연결 + 공개키 교환 중계 | 연결 메타·공개키 |
| `digest-relay` | **E2EE 암호문** 수신·부모 전달 | **암호문+라우팅 토큰만, 복호 불가, 단기** |

> **자산 스토리지·OTA 없음.** 응답뱅크·오디오·온디바이스 모델은 **앱 번들 내장**, 앱 업데이트로 갱신. (오브젝트 스토리지 불필요)
> `digest-relay`는 **암호문 중계자**다. 다이제스트는 **종단간 암호화(E2EE)** 되어 자녀 폰에서 암호화되고 부모 폰에서만 복호된다 — 백엔드는 평문을 보지 못한다. 설계 상세: `docs/50_데이터_프라이버시_구현.md` §1.

## 6. 응답 뱅크 & 모델 자산
- **응답 뱅크**: `packages/response-bank`에 intent 스키마 + 대사 원본(JSON) + 오디오. **앱 번들에 내장**(자산 스토리지/OTA 없음, 앱 업데이트로 갱신).
- **오디오**: 성우 녹음(고빈도 코어) + 보이스 클론(롱테일). 사전 녹음 클립 → 온디바이스 재생(지연 0).
- **모델**: 라우터·A축 보조에 **Gemma 4 E2B(후보)** 온디바이스 추론(MediaPipe LLM Inference/MLC). function calling으로 intent 출력, 멀티모달로 콘텐츠 판단. **LLM은 화자가 아니라 라우터/판단기**(불변식 #3). 저사양 폴백(경량 분류기)을 인터페이스로 분리. 모델 번들 내장.
- 상세: `docs/30_대화_응답뱅크.md`, `docs/20_스크리닝_엔진.md` (예정).

## 7. 데이터 저장·보존 정책 (요약)
| 데이터 | 어디에 | 보존 |
|---|---|---|
| 화면 콘텐츠 원문·상세 사용 로그 | 메모리(Ephemeral) | **즉시 폐기, 미저장·미전송** |

| 요정 관계·기억 상태 | 자녀 폰 로컬(암호화) | 지속(관계 연속성) |
| 맥락 다이제스트 | 부모 폰(주) / 백엔드(중계, 단기) | 부모측 보존, 서버 최소 · **E2EE 암호문**(서버 복호 불가) |
| 동의·계정·페어링 메타 | 백엔드 | 표준 |

## 8. 두 디바이스 케이스의 아키텍처 차이
- **케이스 A (자녀 전용폰)**: `sensing`이 상시 구동, DevicePolicyManager로 보호. 요정 상시 거주. `session` 모듈 불필요.
- **케이스 B (부모폰 공유)**: `session` 모듈이 **요정 모드 진입/이탈로 데이터 경계를 강제.** 세션 밖에서는 `sensing`이 파이프라인에 진입조차 못 한다(부모 격리, 불변식 #4). 세션 판정의 명시성이 핵심 — 암묵 추정 금지.
- 공통: 부모 앱·다이제스트는 동일. A를 레퍼런스로 먼저 완성, B는 세션 경계를 별도 트랙으로.

## 9. 신뢰 경계 & 컴플라이언스 매핑
| 경계 | 위협 | 방어 | 근거(§8) |
|---|---|---|---|
| 온디바이스 ↔ 네트워크 | 원시 데이터 유출 | 단일 `DigestPayload` 게이트, 그 외 송신 금지 | §3 최소수집 |
| 다이제스트 ↔ 백엔드/네트워크 | 서버 침해·도청·영장으로 내용 노출 | **E2EE**(자녀 암호화→부모만 복호), 서버는 암호문만 | §3, §23 |
| A축 분류 ↔ 저장소 | 민감정보 영속화 | 라벨 즉시 폐기, Ephemeral 타입 | §23 |
| 센싱 ↔ 동의 | 동의 없는 처리 | 동의 확인 게이트 선행 | §22의2①, 시행령§17의2 |
| 자녀 세션 ↔ 부모 사용 | 부모 감시 | 세션=데이터 경계(케이스 B) | §3 목적구속 |
| 요정 발화 | creepy/유해 발화 | 라우터+뱅크(생성 차단) | (제품 신뢰) |

## 10. 오픈 이슈 / 결정 대기
1. ~~**다이제스트 종단간 암호화** 채택 여부~~ → **채택 확정.** 설계: `docs/50_데이터_프라이버시_구현.md` §1 (X25519 ECDH + HKDF + XChaCha20-Poly1305, ephemeral 송신키, Keystore).
2. **A축/라우터 모델**: **Gemma 4 E2B(후보)** — function calling 라우터 + 멀티모달 A축 보조. 저사양 기기 폴백(경량 분류기) 필요. 최종 선택은 앱 골격 후 벤치마크 → `docs/20`. (B축은 LLM 불필요, 규칙 엔진)
3. ~~라우터 구현 방식~~ → **Gemma function-calling 우선, 규칙 폴백.** 자유 텍스트 미사용(불변식 #3).
4. **케이스 B 런처 방식**: 전용 런처 vs Android Kids Space/제한 프로필 활용 가능 범위.
5. **DevicePolicy/권한 회수 방지** 수준 (케이스 A) — 7~9세 대상이라 과도한 잠금은 불필요.
6. 부모 앱 iOS 확장 시점(자녀 앱과 분리 가능).
7. 결제·동의 결합 플로우의 구체 UX(§17조의2 어느 호 조합).
